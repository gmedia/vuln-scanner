# Spec: Dual language (id / en) — i18n v1

**Status:** **S1–S7 on `main`** (#367–#373) — SPA catalogs + switcher, Guide, notify/executive locale, `users.locale`, SIEM+Admin chrome. **Do not re-implement S1–S7.** Residual: catalog drift / missing keys on new pages only.
**Goal:** Let operators and customers use the product in **Bahasa Indonesia** or **English** without blocking attach revenue or rewriting the scan engine.
**Suggested epic label:** **P8-i18n** (guide §1.3 now uses **P8** for Uptime). Does **not** jump ahead of GTM unless the user reorders.
**Depends:** SPA React/Vite + `i18next` / `react-i18next` **on `main`** · P1 executive HTML + notify · P2 Workspace · P4 soft dual-brand strings · freeze testids in `handoff.md`.
**Commercial lock:** SKU **D1** — report language v1 is **Bahasa Indonesia**; English is **later**, not a v1 invoice requirement ([`sku-scan-secure-addon.md`](../commercial/sku-scan-secure-addon.md)).
**Not this epic:** extra locales (zh, ja, …) · RTL · translating Wazuh Manager UI · translating CVE/OSV vendor text · legal `/terms` `/privacy` (Cluster B still blocked until legal URLs exist).

---

## 1. Problem

| Today | Pain |
|-------|------|
| UI copy is **mixed hardcoded** EN + ID (e.g. Dashboard “Jadwal scan”, ScanDetail “HTML teknis / Laporan eksekutif”) | No single locale; bilingual users see a mash-up |
| No `i18next` / `react-intl` / message catalogs | Every new string is a one-off in TSX |
| Executive HTML + AM email kit are **ID-first** (D1) | English managers / multi-national colo accounts cannot pick EN reports without a product switch |
| `index.html` `lang` is static | a11y / SEO wrong for EN users |
| Playwright / Vitest assert **visible Indonesian strings** | Naive string swap will fail CI unless tests use testids or locale fixtures |
| Agent chat is Bahasa; code/PRs English | Fine for humans; **product UI** still needs a locked default |

Attach upsell is ID-market first (GMD colo/VPS). English is for **corporate / multi-national** accounts and future `sinexis.app` visitors — not a rebrand gate.

---

## 2. Goals

1. **Two locales only:** `id` (Bahasa Indonesia) and `en` (US English copy; `en-US` BCP 47).
2. **Default locale = `id`** (matches D1 + AM kit). First-time visitor without a stored preference → Indonesian.
3. **User-selectable language** in the authenticated shell (and public landing) that persists (`localStorage` + optional `User.locale` later).
4. **SPA chrome, auth, attach, workspace, Guard thin, SIEM flag-off copy** all go through message catalogs — not ad-hoc TSX literals.
5. **Customer-facing exports** (executive HTML, notify email subject/body templates) honor the **same locale as the schedule owner or org preference** (see §4).
6. **Technical finding text** (CVE titles, nmap output, header names) stays **source language** (usually English); wrap with a short ID/EN chrome, do not machine-translate CVEs in v1.
7. **Tests** stay green: freeze testids; prefer `getByTestId` over raw copy; add a locale fixture for both catalogs.
8. **Docs:** this spek + one-line pointer in the execution guide when S0 lands. No customer PII in catalogs.

---

## 3. Non-goals (explicit)

| Out | Why |
|-----|-----|
| Third language | Scope lock; catalogs stay two JSON trees |
| Auto-detect from `Accept-Language` as **override of default** without user choice | GMD operators often have `en` browser + ID customers; default **id** is safer |
| Translating **OSV/CVE descriptions**, nmap scripts, SSL cipher names | Integrity of scan evidence |
| Translating **Wazuh Dashboard / Discover** | Guard is thin; P7 SIEM is a separate surface |
| In-app CAT / Crowdin / paid TMS in v1 | Two locales, in-repo JSON is enough |
| Per-org legal pages | Cluster B blocked |
| Changing SKU prices or invoice language in finance | GMD billing system, not this SPA |
| Hard domain cut / P4 redo | Soft dual-brand already shipped |
| AI “improve Guide TOC” as part of i18n | TOC structure frozen; only wrap strings |

## 4. Defaults (locked unless user overrides)

| Topic | Default |
|-------|---------|
| Default locale | **`id`** |
| Alternate | **`en`** |
| Persistence v1 | `localStorage` key `sinexis.locale` (`id` \| `en`) |
| Persistence v1.1 (optional slice) | `users.locale` + PATCH `/api/auth/me`; JWT need not carry locale |
| Org override | **None in v1** — language is **per browser/user**, not per workspace. Exports: **schedule owner’s stored locale**, else `id` |
| Detection | Optional hint: if no stored key and `navigator.language` starts with `en`, **still default `id`** unless product later unlocks “browser hint” (open question §11) |
| HTML | Set `<html lang="id">` or `lang="en"` on change |
| Dates | `date-fns` locale `id` / `enUS`; timezone unchanged (existing app TZ) |
| Numbers / IDR | Locale-aware grouping; currency label **IDR** stays; SKU figures already in IDR |
| Direction | LTR only |
| Fallback | Missing key → `id` string → key name in dev only (never blank) |
| Brand | “Sinexis” / “VulnScanner” **untranslated**; module names Scan / Guard / SIEM stay |
| Testids | **Do not rename** frozen ids (`user-menu`, `org-switcher*`, `export-executive`, `rescan-button`, `guard-state`, `guide-desktop-toc`, …) |
| Copy tone | ID: formal-sopan, AM-adjacent (like `am-wave1-email-id.md`). EN: concise product English, not marketing fluff |

## 6. Technical approach (recommended)

### 6.1 Library

**Use `i18next` + `react-i18next`** (JSON catalogs, ICU later if needed, large ecosystem). Do **not** invent a custom `t()` unless the user forbids new deps.

- Namespaces: `common`, `auth`, `scan`, `schedules`, `workspace`, `guard`, `siem`, `guide`, `admin`, `emails` (emails may live backend-side).
- Files: `frontend/src/locales/{id,en}/*.json`.
- Init in `main.tsx` before `createRoot`.
- Language switcher: compact **ID | EN** in header (next to user menu), `aria-label` from catalog.

### 6.2 Backend

v1 may keep API messages in English **machine codes** + optional `message_key`. Humanization in SPA.

**S3 (exports/notify):** backend loads `backend/app/locales/{id,en}/*.json` (or Jinja templates) when rendering executive HTML and email. Locale argument: `?lang=` on export **or** stored user locale. Default `id`.

Do not fork the scan pipeline per language.

### 6.3 Routing / SEO

No `/en/` prefix in v1 (SPA is app-like). Landing: same path, `lang` attribute only. Optional `?lang=en` for AM screenshots.

### 6.4 Guide / large markdown

`/guide` is TSX today. Extract headings + body to `guide.json` (or MDX later). **Must not** rename `guide-desktop-toc` or re-introduce a second `SidebarProvider`. Nested TOC labels come from the same keys as headings.

## 8. Copy rules

1. **Do not** mix languages in one locale file.
2. Keep **product nouns**: Scan, Guard, SIEM, credits, org.
3. ID: “jadwal scan”, “laporan eksekutif”, “batas 10 jadwal aktif per organisasi” — reuse Wave B, don’t clever-rewrite.
4. EN: “Scan schedule”, “Executive report”, “Limit 10 active schedules per organization”.
5. Errors: user-safe; no stack traces.
6. Never put production hosts, emails, or SID lists in locale JSON.

## 9. Testing

| Layer | Expectation |
|-------|-------------|
| Vitest | Render with `I18nextProvider`; default suite **`id`** to match current assertions **or** migrate assertions to testids in the same PR that extracts strings |
| Playwright | Keep frozen testids; one smoke `locale=en` on login + dashboard |
| Backend | Executive HTML contains ID strings by default; EN when `lang=en` |
| CI | Catalog key parity check: every key in `en` exists in `id` and vice versa (script in `frontend/` or pre-commit) |

**Anti-pattern:** `getByText('Jadwal scan')` without locale fixture after S2.

## 11. Open questions (answer before S1 code)

6. **AM email kit** in git: keep ID-only, or add `am-wave1-email-en.md`? **Docs-only, not S1.**
