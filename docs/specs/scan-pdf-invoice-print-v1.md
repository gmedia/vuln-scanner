# Spec: Scan print-to-PDF + invoice HTML print

**Status:** **S0 draft** (this file). S1+ only after explicit `implement` / `buat` / `kerjakan` **and** a named slice (`S1a` or `S1b`). **Do not** ship app code in the S0 PR.
**Goal:** Let a GM **Print / Save as PDF** the existing executive (and technical) scan HTML, and let org admin / platform admin **print a Scan or Host invoice** — without a PDF library or payment gateway.
**Epic:** product-depth follow-on to P1 S4 + invoice v1. **Not** a new P-letter. Does **not** replace Scan attach, invoice pay loop, or P15 chrome.
**Depends:** `GET /api/scan/{id}/export` (`json` \| `html` \| `executive`) · `render_executive_html` · `_render_pdf_html` (legacy name — **HTML**, not PDF) · `org_invoices` + `InvoiceItem` · bank env `INVOICE_BANK_*` · i18n executive locale (`id` default).
**Commercial:** not a new list-price SKU. Guide §1.3.1 **#1** = Print S2 (`format=pdf` / WeasyPrint). S1a/S1b **shipped**. Invoice PDF stays I10 **out**. Host invoice = **H9 shipped**.
**Not this epic:** WeasyPrint / reportlab / wkhtmltopdf / headless Chromium as a product PDF engine; `format=pdf` bytes; Celery PDF; public invoice URL; Palatino / `#0a7`; restyle `components/ui`; P15 chrome; GTM.

2. Bank copy only when invoice `status=sent` (I8/I9). Draft/void HTML **must not** contain `bank_account`.
3. No PII / real bank numbers / customer paths in git or fixtures.
4. Frozen testids stay: `export-executive`, `workspace-billing`, `nav-admin-invoices`.
5. Design system: `--primary` `hsl(142 71% 45%)`, Inter / `--font-sans`. **No** Palatino, **no** `#0a7`, **no** native `<select>`, primary actions = `Button`.
6. `GIT_MASTER=1`. Never work on `main`. Playwright ≠ Guard enroll.

## 1. Problem

| Today | Pain |
|-------|------|
| Attach export is **HTML download** (JSON / technical / executive) | GM asks for a **PDF**. Opening the file and Ctrl+P works only by accident (thin `@media print`, no `@page`, download-as-attachment does not open a print dialog). |
| `_render_pdf_html` **looks** like PDF | Agents will “finish PDF” by adding WeasyPrint or `format=pdf` and break tests that assert 400. |
| Invoice v1 is JSON + compact Billing list | Ops/customer cannot print `SX-YYYYMM-NNNN` for bank transfer. I10 deferred “HTML print later”; there is **no** invoice HTML. |
| Invoice I10 forbids a **PDF library** | Server-side `.pdf` for invoices would reopen I10. Scan and invoice must not share a `PdfService`. |

This is **print chrome on documents we already have** (scan) plus **one new print view** (invoice). Not a new report engine.

## 2. Goals

1. **Track A (scan):** From ScanDetail Export tab (and optionally Schedules executive shortcut), the operator can **open** executive HTML in a context that supports **Print / Save as PDF** (browser). Same for technical HTML. Do **not** rewrite cover / diff / top-5 / next-steps copy.
2. Thicken print CSS on both scan HTML documents: `@page` A4, hide SPA chrome if viewed in-app, avoid broken table rows (`break-inside: avoid` on cover / finding blocks). Brand tokens match `:root`.
3. **Track B (invoice):** Printable layout for one Scan invoice: number, seller line (from env, may be `"—"`), bill-to org name, SKU, seats (from catalog snapshot not required — `sku` + `amount_idr` + period are enough), period, status, amount IDR. Bank block **only** if `sent`. Available on Workspace Billing (owner/admin) **and** `/admin/invoices`.
4. i18n `id` / `en` for new Print labels. Executive body locale stays `?lang=` / `sinexis.locale` (default `id`).
5. Tests: pytest HTML contains `@media print` (scan) / invoice print HTML has number and **omits** bank on draft; Vitest Print buttons + frozen testids; IDOR unchanged.
6. Docs: this file; guide §1.3.1 pointer; invoice spec I10 pointer. **No** customer URLs, bank numbers, or `.pdf` binaries in git.

## 6. AuthZ

| Action | Who | Fail |
|--------|-----|------|
| Print / open scan executive or technical HTML | Same as `GET /api/scan/{id}/export` (JWT or API key; job in caller’s org) | Other org → existing 404/403 |
